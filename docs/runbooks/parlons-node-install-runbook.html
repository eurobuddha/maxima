For Parlons Node 0.2.143 (release tag node-v0.2.143): the plain jar parlons-node-0.2.143.jar and the fleet jar parlons-node-fleet-0.2.143.jar. Every command, flag, port, default and file in this runbook comes from the installer ops/get-parlons-node.sh, the deploy script ops/deploy-parlons-node.sh, the node source (node/, core/, server/) and the Minima fork the jar embeds. Where the code has no value, this runbook says so.

This is the install document: it takes a fresh Linux machine to a verified, paired, backed-up node. The Operator's Manual is the reference for everything after that (every property, TLS fronting, the DEX cape, monitoring, troubleshooting in depth).

Host names in examples (node.example.com, 203.0.113.10) are placeholders.

1What you are installing

A Parlons Node is one Java process that runs:

One seed drives everything. On first boot the node's wallet seed is copied into identity.txt, and the relay identity (Mx…) and the account address (MAX#…) are derived from it. That seed is a spendable wallet. It is never printed to a log; you back it up in §11.

Who needs a Parlons Node? Most people do not. An always-on account without the chain runs in 1 GB with get-parlons-cloud.sh. Run a Parlons Node when you want a full copy of the chain, a relay for the network, a wallet gateway for phones, or a fleet endpoint.

Notes on the choice:

  • The installer sizes the node itself: with 3.5 GB of RAM or more it turns MegaMMR on with a 2 GB heap; below that, a plain node with a 768 MB heap. The fleet's own experience is that a MegaMMR node wants a 3 GB heap (2 GB and 2.5 GB heaps looped on out-of-memory). So on a 4 GB box pass --no-megammr explicitly, and on an 8 GB box pass --heap 3g. Do not accept the installer's MegaMMR default on a 4 GB machine.
  • MegaMMR is only useful once a snapshot is imported (§5, step 5). The initial sync does not fill it. Until the import, balances for existing addresses come back empty.
  • Profile C is Linux x86_64/aarch64 only. A 32-bit Raspberry Pi OS cannot be a fleet box. A Mac refuses fleet mode with a clear message. Existing fleet boxes that already run the three separate keets services are not migrated by this runbook; it is for new boxes.
  • Mac or Windows: install Parlons Desktop instead. The jar is Linux-with-systemd on a server.

3Pre-flight checklist

Run these on the target machine as root (or with sudo) before you install anything. Each check says what must come back.

  1. Linux with systemd. Any mainstream distribution (Debian, Ubuntu, Fedora, Alpine, Arch). This must print systemd: 
    ps -p 1 -o comm=
  2. CPU architecture. For profile C this must print x86_64 or aarch64: 
    uname -m
  3. RAM. Compare with the table in §2: 
    free -m | awk '/Mem:/ {print $2 " MB"}'

    The installer refuses under 900 MB, and under 1900 MB for --fleet.

  4. Disk. The chain grows. Budget for the chain, a 460 MB MegaMMR snapshot while importing, and any NFT files or relay blob shelf. Check free space where /var/lib lives: 
    df -h /var/lib
  5. Java. 11 or newer is required; 21 or newer is recommended (the relay then uses virtual threads and its connection cap rises from 512 to 4096). The installer adds a headless JRE if java is missing. If Java is already there, check it and that the jdk.httpserver module is present (the gateway, admin RPC, panel and DEX cape need it): 
    java -version
java --list-modules | grep jdk.httpserver

    The second command must print one line.

  6. Clock. A node with a wrong clock never attaches. This must show synchronized: yes: 
    timedatectl | grep -E 'synchronized|NTP'
  7. Ports free. Nothing may already hold the node's ports. This must print nothing: 
    ss -ltnp | grep -E ':(9001|9003|9004|9005|9501|9585|9587|9602) '
ss -lunp | grep -E ':(9501|49737) '

    If a stock Minima node holds 9001, plan to move the node (§8, parlons.node.port). If an old maxima-relay.service holds 9501, plan to replace it (§7, step 6).

  8. Public address and DNS (profiles B and C). The box must have a global IPv4 address, and for profile B a DNS name pointing at it. This must print a public address, not 10.x, 172.16-31.x, 192.168.x or 100.64-127.x: 
    ip -4 -o addr show scope global | awk '{print $4}'
  9. Provider firewall. Open the inbound ports for your profile (§2) in the cloud console (Hetzner, Vultr, AWS, …) or forward them on your home router. The installer only opens them in ufw/firewalld on the box; a provider firewall sits in front of that.
  10. Outbound access. The box must reach GitHub (the download), the rootnode 65.109.31.226:9001, the mesh relays on 9501 and, for keets, UDP 49737 to the DHT bootstraps. On a default-deny-outbound box, allow those first.
  11. A terminal. Run the installer in an interactive SSH session. Without a TTY it skips the pairing-password and QR steps (you can run them later with parlons-pair).

4Profile A: plain full node (one command)

A full Minima node plus a relay plus your always-on account, without MegaMMR. 2 GB of RAM is plenty; the installer accepts 1 GB.

4.1 Install

  1. Open TCP 9001 and TCP 9501 inbound in the provider firewall or router (§3, step 9).
  2. In an SSH session on the box, run the installer with --no-megammr: 
    curl -fsSL https://raw.githubusercontent.com/eurobuddha/maxima/main/ops/get-parlons-node.sh | bash -s -- --no-megammr

    Pass --heap 1g as well if the box has 4 GB or more and you want the node to have more room.

  3. Watch the five steps:
    1. [1/5] Java — installs default-jre-headless (apt), java-21-openjdk-headless (dnf), openjdk21-jre-headless (apk) or jre-openjdk-headless (pacman) if needed, plus qrencode.
    2. [2/5] Newest Parlons Node release — finds the newest node-v… release, downloads parlons-node-<ver>.jar and refuses it unless its sha256 matches the release's SHA256SUMS. It prints sha256 verified: <hash>. Compare with §17.3.
    3. [3/5] Service (starts at boot) — creates the maxima system user, /var/lib/parlons-node (mode 700), /opt/maxima/parlons-node.jar (a symlink to the versioned jar), /usr/local/bin/parlons-pair and the hardened unit /etc/systemd/system/parlons-node.service. It prints the sizing: heap 768m (MemoryMax 1280M), MegaMMR false, syncing from 65.109.31.226:9001.
    4. [4/5] Firewall — allows 9001/tcp and 9501/tcp in ufw or firewalld when one is active.
    5. [5/5] Waiting for your account to come online — up to 4 minutes, then prints your account address in full (MAX#…).
  4. When asked, type an admin pairing password twice. It protects every future invitation for your own devices. Then type it once more: the installer draws the QR code your phone scans (§10).
  5. Note the two lines the installer prints last: BACK UP YOUR SEED and the manual link. Do §11 today.

4.2 What the installer wrote

The unit's ExecStart for profile A is exactly:

ExecStart=/usr/bin/java -Xmx768m \
    -Dparlons.node.data=/var/lib/parlons-node \
    -Dparlons.node.port=9001 \
    -Dparlons.relay.port=9501 \
    -Dparlons.node.megammr=false \
    -Dparlons.node.rootnode=65.109.31.226:9001 \
    -jar /opt/maxima/parlons-node.jar

(/usr/bin/java is whatever readlink -f "$(command -v java)" resolved to on your box.) Everything else in the unit is the hardening and the resource ceilings shown in §7. The admin RPC is off, the DEX cape is off, there is no keets sidecar, and the mesh uses the compiled-in bootstrap list.

4.3 Check it

Go to §9 (first start) and §12 (verify from outside).

5Profile B: wallet gateway node with MegaMMR

A node that phones can use as a wallet gateway. It needs 8 GB of RAM, a 3 GB heap, the admin RPC (for the MegaMMR import), a DNS name with TLS in front of the gateway, and a one-time MegaMMR snapshot import. The deploy script does the node part in one command; the TLS front is yours.

5.1 Install with the deploy script (from your own computer)

The deploy script runs on your computer against a fresh box you reach over SSH as root with a key. Running it again later is the update path.

  1. Clone the repository on your computer: 
    git clone https://github.com/eurobuddha/maxima.git
cd maxima
  2. Download the jar and the checksums into dist/, and verify. The hash must match §17.3: 
    mkdir -p dist && cd dist
curl -fLO https://github.com/eurobuddha/maxima/releases/download/node-v0.2.143/parlons-node-0.2.143.jar
curl -fLO https://github.com/eurobuddha/maxima/releases/download/node-v0.2.143/SHA256SUMS
grep ' parlons-node-0.2.143.jar$' SHA256SUMS | shasum -a 256 -c -
cd ..

    It must print parlons-node-0.2.143.jar: OK.

  3. Check key-based root SSH (the script uses BatchMode=yes and cannot answer a password prompt): 
    ssh -o BatchMode=yes root@node.example.com true && echo ssh-ok
  4. Open TCP 9001, 9501, 80 and 443 in the provider firewall.
  5. Run the deploy. This is the full profile B command; every flag is explained in §8.4: 
    ops/deploy-parlons-node.sh root@node.example.com \
    --jar dist/parlons-node-0.2.143.jar \
    --heap 3g \
    --rootnode 65.109.31.226:9001 \
    --rpc \
    --megammr-seed https://eurobuddha.com/mega.mmr \
    --public https://node.example.com/parlons-node \
    --dex 9602 --dex-public https://node.example.com/dex-relay

    Leave out the --dex … line if you do not want to carry Dexicon's order book. Never pass --dex without --dex-public: without the public URL the DEX cape binds 0.0.0.0 and the script opens the port as plain HTTP to the internet.

    What the script does, in order: installs a headless JRE if needed, creates the maxima user and /var/lib/parlons-node, uploads the jar to /opt/maxima/parlons-node-0.2.143.jar and verifies its sha256 before flipping the parlons-node.jar symlink, installs parlons-pair, writes the unit, opens 9001 and 9501 in ufw/firewalld, starts the node, waits for the relay port, then (step 6c) downloads mega.mmr into the data directory, imports it over the loopback RPC, restarts, and proves megammr.mmr is larger than 1 MB. It ends with the account address, the Mx… identity and the gateway bearer token, all in full.

  6. Set up the TLS front (§5.3). The public URLs are already in the unit from --public and --dex-public, so no unit edit is needed.
  7. Pair your phone (§10), back up the seed (§11), verify from outside (§12).

5.2 Install with the one-line installer instead

If you prefer to work on the box, the installer gets you most of the way; you then add three properties and import the MegaMMR by hand.

  1. Open the ports (step 4 above) and run the installer with an explicit heap: 
    curl -fsSL https://raw.githubusercontent.com/eurobuddha/maxima/main/ops/get-parlons-node.sh | bash -s -- --heap 3g

    With 3.5 GB of RAM or more the installer turns MegaMMR on. --heap 3g gives it MemoryMax=4096M.

  2. Edit the unit to turn on the admin RPC and name the public URL. Back it up first: 
    cp /etc/systemd/system/parlons-node.service /etc/systemd/system/parlons-node.service.before-gateway
nano /etc/systemd/system/parlons-node.service

    Add these lines inside ExecStart, before -jar (each line ends with a backslash):

    -Dparlons.node.rpc=true \
-Dparlons.node.public=https://node.example.com/parlons-node \
  3. Reload and restart, then check the boot line says admin rpc 127.0.0.1:9005 (loopback-bound): 
    systemd-analyze verify /etc/systemd/system/parlons-node.service
systemctl daemon-reload && systemctl restart parlons-node
sleep 25; journalctl -u parlons-node -b --no-pager | grep -E 'Parlons Node|admin rpc' | grep -v seed
  4. Import the MegaMMR snapshot (§5.4).
  5. Set up the TLS front (§5.3).

5.3 The TLS front

The gateway (127.0.0.1:9585) and the DEX cape (127.0.0.1:9602) speak plain HTTP on loopback. A web server on the box terminates TLS and forwards two paths:

Public pathForward toStrip
https://node.example.com/parlons-node/…http://127.0.0.1:9585/…/parlons-node
https://node.example.com/dex-relay/…http://127.0.0.1:9602/…/dex-relay

Never forward the admin RPC (9005), the panel (9587) or MDS.

With Caddy (gets its own certificate):

node.example.com {
    handle /dex-relay/* {
        uri strip_prefix /dex-relay
        reverse_proxy 127.0.0.1:9602
    }
    handle /parlons-node/* {
        uri strip_prefix /parlons-node
        reverse_proxy 127.0.0.1:9585
    }
    # a catch-all `handle { … }` for your own site goes LAST
}

Use handle + uri strip_prefix, not handle_path: Caddy sorts handle_path after a catch-all handle, which then answers every DEX request with your web page.

With nginx, inside the server { listen 443 ssl; … } block:

location /dex-relay/ {
    proxy_pass http://127.0.0.1:9602/;
    proxy_http_version 1.1;
    proxy_set_header Host $host;
    proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
    proxy_read_timeout 60s;
}
location /parlons-node/ {
    proxy_pass http://127.0.0.1:9585/;
    proxy_http_version 1.1;
    proxy_set_header Host $host;
    client_max_body_size 2m;
}

The X-Forwarded-For line is required for the DEX block: without it every DEX client shares one rate-limit bucket. Apache's equivalent is in the manual (§11).

Then test from another machine:

curl -s https://node.example.com/dex-relay/dex/health          # {"ok":true,"version":"0.1.5",...}
curl -s -o /dev/null -w '%{http_code}\n' -X POST https://node.example.com/parlons-node/cmd   # 401

5.4 Import the MegaMMR snapshot (once)

The deploy script's --rpc --megammr-seed already did this. Do it by hand after the installer path, or whenever megammr.mmr is under 1 MB.

  1. The admin RPC must answer: 
    curl -s http://127.0.0.1:9005/status | head -c 200; echo
  2. Check the current size (under 1 MB = empty): 
    stat -c %s /var/lib/parlons-node/1.1/databases/megammr.mmr
  3. Download the snapshot into the data directory (about 460 MB; -c resumes): 
    cd /var/lib/parlons-node
wget -c -O mega.mmr https://eurobuddha.com/mega.mmr
chown maxima:maxima mega.mmr
  4. Import over loopback. It must reply "status":true and ends with a node shutdown: 
    curl -s -m 3600 'http://127.0.0.1:9005/megammr%20action:import%20file:/var/lib/parlons-node/mega.mmr'
  5. Bring the node back and check the file is now over 1 MB: 
    systemctl restart parlons-node
sleep 20; stat -c %s /var/lib/parlons-node/1.1/databases/megammr.mmr
  6. Query a funded address. The balance must not be empty: 
    curl -s 'http://127.0.0.1:9005/balance%20megammr:true%20address:<a funded Mx or 0x address>'
  7. Delete the download: 
    rm -f /var/lib/parlons-node/mega.mmr

Order matters: if you also adopt an existing seed phrase (§13.6), do that before the import. A resync resets the chain databases and throws the imported MegaMMR away.

5.5 Confirm the gateway is advertised

Phones learn the gateway from the relay greeting only when MegaMMR is on, parlons.node.public is set and the relay is on. Check:

journalctl -u parlons-node -b --no-pager | grep -E 'wallet gateway (up|advertised|FAILED)'

You want wallet gateway advertised to phones: https://node.example.com/parlons-node/cmd. Then test the token (§12, step 4).

6Profile C: fleet endpoint (every service in one jar)

The fleet jar makes a fresh, directly reachable Linux box a full endpoint for every service with one install. On top of the node, cape, gateway and account it turns on:

  • the Minima server role (-server: the node accepts inbound P2P links),
  • the keets transport for the embedded node,
  • a public HyperDHT bootstrap node on UDP 49737,
  • a keets mailbox (store-and-forward for phones that are offline),
  • the admin RPC (loopback) and, when you give it a TLS URL, the DEX cape.

The keets sidecar runs inside the jar's own Node.js (v20.20.2, embedded for linux-x64 and linux-arm64, with keets sidecar 1.3.0), extracted once into /var/lib/parlons-node/runtime/node-v20.20.2+sidecar-1.3.0/. Nothing else is installed on the box.

6.1 Requirements that differ from A and B

  • x86_64 or aarch64 (uname -m). Anything else is refused: "A fleet box needs x86_64 or aarch64".
  • 2 GB of RAM minimum (the installer refuses under 1900 MB). The unit's MemoryMax is heap + 512 MB + 1 GB for the sidecar. 4 GB is comfortable; 8 GB with --heap 3g for MegaMMR.
  • A public IPv4 address on the box itself. The installer detects the box's global-scope address and refuses private, loopback and CGNAT (100.64/10) addresses. Behind NAT, pass --public-host <the address the world reaches you on> and forward every port below.
  • Inbound ports: TCP 9001, TCP 9501, UDP 9501 (STUN), UDP 49737 (the DHT). The installer opens all four in ufw/firewalld; open them in the provider firewall too.
  • The unit gains AF_NETLINK (the sidecar's udx-native watches interfaces over netlink) and TasksMax=2048.

6.2 Install

  1. Open TCP 9001, TCP 9501, UDP 9501, UDP 49737 (and 80/443 if you will front a DEX cape) in the provider firewall.
  2. In an SSH session on the box, run the installer with --fleet. Add --no-megammr on a box under 8 GB, --heap 3g on one with 8 GB or more: 
    curl -fsSL https://raw.githubusercontent.com/eurobuddha/maxima/main/ops/get-parlons-node.sh | bash -s -- --fleet --no-megammr

    If the box's address is not on one of its interfaces (NAT), name it:

    curl -fsSL https://raw.githubusercontent.com/eurobuddha/maxima/main/ops/get-parlons-node.sh | bash -s -- --fleet --public-host 203.0.113.10 --no-megammr
  3. The installer downloads parlons-node-fleet-0.2.143.jar (about 109 MB), verifies its sha256 against the release's SHA256SUMS (§17.3), and writes the unit with two extra properties: 
    ExecStart=/usr/bin/java -Xmx768m \
    -Dparlons.node.data=/var/lib/parlons-node \
    -Dparlons.node.port=9001 \
    -Dparlons.relay.port=9501 \
    -Dparlons.node.megammr=false \
    -Dparlons.node.rootnode=65.109.31.226:9001 \
    -Dparlons.fleet=true -Dparlons.public.host=203.0.113.10 \
    -jar /opt/maxima/parlons-node.jar

    plus RestrictAddressFamilies=AF_INET AF_INET6 AF_UNIX AF_NETLINK, TasksMax=2048 and the larger MemoryMax. /opt/maxima/parlons-node.jar is a symlink to the fleet jar.

  4. Set the admin pairing password and scan the QR as in profile A (§10).
  5. The installer then waits up to 2 minutes for the sidecar and prints the FLEET ENDPOINT banner (§6.4). Copy it somewhere safe; you need the mailbox pubkey for §6.5.

Read it again any time:

journalctl -u parlons-node --no-pager | grep -A4 'FLEET ENDPOINT' | tail -5

6.5 Get the box into the fleet lists (one message to the list maintainer)

The Minima P2P mesh and the relay mesh pick the box up by gossip; nothing to do. Two things need a human:

  1. The keets mailbox joins the fleet only when its pubkey is signed into the published list. Send the maintainer of https://eurobuddha.com/keets/mailboxes.json the keets mailbox line from the banner, in full. The maintainer runs the publish it: command the node printed (the signing key never leaves their machine) and publishes the new mailboxes.json.   2. The DHT bootstrap 203.0.113.10:49737 becomes a first-contact bootstrap for new installs only when it is added to the fork's compiled-in KEETS_BOOTSTRAP list at the next release. 11Back up the seed and the identity

The seed is a wallet. The 24-word phrase, identity.txt and any adopted seed.txt can all spend funds. Never print them to a log, a ticket, a chat or a recorded terminal.

There are two secrets with one origin: the wallet seed in the node's vault (/var/lib/parlons-node/1.1/…) and the identity phrase in /var/lib/parlons-node/identity.txt (mode 600), from which the Mx… identity and the MAX# are derived. On a fresh node they are the same phrase; after a wallet resync or an identity import they differ, so back up both.

  1. Wallet phrase. The admin RPC must be on (-Dparlons.node.rpc=true; profile A: add it temporarily, §7 step 5, or read it once via a paired device's backup feature). In an unrecorded session on the box: 
    curl -s http://127.0.0.1:9005/vault

    Write the 24-word phrase on paper or into offline storage. Clear the terminal scrollback.

  2. Identity and account files. Stop the node for a consistent copy, archive everything except the chain and NFT temp files, move the archive off the box, delete it there: 
    systemctl stop parlons-node
tar -C /var/lib/parlons-node -czf /root/parlons-node-backup.tgz --exclude='./1.1' --exclude='./nft/tmp' --exclude='./runtime' .
systemctl start parlons-node
chmod 600 /root/parlons-node-backup.tgz

    Then from your computer: scp root@node.example.com:/root/parlons-node-backup.tgz . and ssh root@node.example.com rm /root/parlons-node-backup.tgz. This archive holds identity.txt, the account (devices, contacts, chat), the relay state, the gateway token and, on a fleet box, the keets mailbox keypair. Treat it like the seed.

  3. The unit and your TLS config: cp /etc/systemd/system/parlons-node.service /root/.
  4. From a paired device, make a portable .pbk account bundle too (Settings → Back up account…).

Never restore the archive onto a second box while the first one runs. One identity runs in one place.

12Verify from outside

systemctl is-active only proves the process runs. Test from another machine on the public internet, never from the box or its LAN (hairpin NAT lies both ways).

  1. TCP reachability of the public ports: 
    nc -z -w 8 node.example.com 9001 && echo p2p-open
nc -z -w 8 node.example.com 9501 && echo relay-open

    Refused at once = host answered, nothing listening (check the service). Timeout = a firewall drops packets (provider console or router). Open = the network path is fine.

  2. The relay end to end, from a checkout of the repository with :core compiled: 
    ops/verify-relay.sh node.example.com:9501

    It attaches two real clients through the relay and makes them talk (greeting, attach, address, contact handshake, delivery both ways, receipt, group fan-out). Exit 0 only if everything passes.

  3. DEX cape (if on): curl -s https://node.example.com/dex-relay/dex/health returns {"ok":true,"version":"0.1.5",…}; /dex/relays lists this node's URL.
  4. Gateway (profile B). On the box, TOKEN=$(sudo cat /var/lib/parlons-node/gateway-token.txt); then from outside: 
    curl -s -H "Authorization: Bearer $TOKEN" -H 'Content-Type: application/json' -d '{"command":"block"}' https://node.example.com/parlons-node/cmd

    must return the node's JSON with "status":true; the same without the header must return HTTP 401; {"command":"vault"} with the header must return HTTP 403.

  5. Loopback-only ports must not answer. This must print nothing: 
    for p in 9003 9004 9005 9585 9587 9602; do nc -z -w 5 node.example.com $p && echo "EXPOSED $p"; done
  6. Fleet box: the mesh and the DHT pick the box up by themselves. Within about 10 minutes other relays list it; after the mailbox list is republished (§6.5), phones use it as a mailbox.

Each is a unit edit (back up the unit, edit, systemd-analyze verify, daemon-reload, restart, check the boot log) unless noted. Full detail in the manual.

13.1 DEX relay cape (Dexicon order book)

13.2 NFT hosting

Always on; it only needs -Dparlons.node.public=https://node.example.com/parlons-node and the /parlons-node/ TLS route. Boot log: nft hosting: … served at https://…/nft/<file>. Files are content-addressed (<sha256>.<ext>, at most 32 MB), uploaded from paired devices only.

13.3 Mesh peers and the blob shelf

-Dparlons.relay.peers=host:port,… to pin the mesh bootstrap list (default: the compiled-in six, §17.4); -Dparlons.relay.blob=1024 for a 1 GB media shelf. Boot log: mesh: N bootstrap peer(s), blob shelf: 1024 MB.

13.4 keets chat bridge on the plain jar

The fleet jar does this itself. On the plain jar: install Node.js on the box, copy a keets sidecar with its node_modules to /opt/maxima/keets-sidecar (the deploy script's --keets does both), then:

"-Dparlons.node.args=-keets -keetssidecar /opt/maxima/keets-sidecar/index.js" \

and RestrictAddressFamilies=AF_INET AF_INET6 AF_UNIX AF_NETLINK. No inbound port is needed (hyperswarm hole-punches). Boot log: keets chat bridge up (KeetChat interop) and keets identity: 0x….

13.5 MDS (MiniHUB)

-Dparlons.mds=true \
-Dparlons.mds.bind=127.0.0.1 \
-Dparlons.node.conf=/var/lib/parlons-node/minima.conf \

with mdspassword=<password> in the conf file (owner maxima, mode 600; a conf file that cannot be read stops the node with exit 2). Reach it through an SSH tunnel to 127.0.0.1:9003. Never bind it publicly.

13.6 Adopt an existing 24-word phrase (keep a relay's or cloud account's identity)

Deploy script: --rpc --seed-from /path/on/box/seed.txt [--archive 65.109.31.226:8001]. It resyncs the wallet to the phrase over the loopback RPC (the phrase travels as a POST body from a mode-600 temp file, never argv), restarts, compares the vault with the file without printing either, pins identity.txt and writes .seed-adopted. Result line to expect: vault MATCHES … - identity preserved (and pinned in identity.txt). Do it before any MegaMMR import. Delete the phrase file from the box once you hold an offline copy.

13.7 Password-locked node

Put the passphrase in /var/lib/parlons-node/passphrase.txt (owner maxima, mode 600; not under /root or /home, which ProtectHome hides; no whitespace, " or ;) and add -Dparlons.node.passphrase.file=/var/lib/parlons-node/passphrase.txt. The node unlocks once per boot. Until then the cape, gateway and account wait and the log says node is password-locked but no passphrase provided.

13.8 Move the node off port 9001 (a stock Minima node on the box)

-Dparlons.node.port=9101 moves P2P to 9101 and the derived ports to 9103/9104/9105. Open the new P2P port and use 9105 in every curl to the admin RPC.

13.9 One public port (home router)

-Dparlons.relay.port=shared: the relay rides the Minima P2P port and only 9001 needs forwarding. Tell users and mesh peers the relay address is host:9001.

14Update, roll back, uninstall

14.1 Update with the installer

Running the installer again fetches the newest release, verifies it, flips the symlink and restarts. Pass the same options you installed with (--fleet, --no-megammr, --heap), because the unit is rewritten from them:

curl -fsSL https://raw.githubusercontent.com/eurobuddha/maxima/main/ops/get-parlons-node.sh | bash -s -- --fleet --no-megammr

Hand-added properties (parlons.node.public, parlons.dex.*, parlons.node.rpc) are lost by an installer re-run: keep your parlons-node.service.before-… backups and re-apply them, or update by hand (next section). A fleet box re-extracts the runtime only when the embedded versions change.

14.2 Update by hand (versioned jars + symlink)

  1. Download and verify the new jar as in §7 step 3, under a .part name, then rename it.
  2. Note the current target and back up the unit: 
    readlink /opt/maxima/parlons-node.jar
cp /etc/systemd/system/parlons-node.service /etc/systemd/system/parlons-node.service.before-parlons-node-<new>.jar
  3. Flip and restart: 
    ln -sfn /opt/maxima/parlons-node-<new>.jar /opt/maxima/parlons-node.jar
systemctl daemon-reload && systemctl restart parlons-node
sleep 25; systemctl is-active parlons-node
journalctl -u parlons-node --since -40s --no-pager | grep -E 'Parlons Node|dex relay|FLEET MODE|Exception' | grep -v seed
  4. Verify from outside (§12). Several boxes: one at a time.

With the deploy script: re-run it with the same flags and the new --jar; a flag you leave out goes back to its default.

14.3 Roll back

cd /opt/maxima && ln -sfn parlons-node-<old>.jar parlons-node.jar
cp /etc/systemd/system/parlons-node.service.before-<what> /etc/systemd/system/parlons-node.service   # if the unit changed
systemctl daemon-reload && systemctl restart parlons-node

Every jar stays in /opt/maxima, so a rollback is one ln -sfn. A box that used to run maxima-relay.service can go back with systemctl disable --now parlons-node && systemctl enable --now maxima-relay.

14.4 Uninstall

curl -fsSL https://raw.githubusercontent.com/eurobuddha/maxima/main/ops/get-parlons-node.sh | bash -s -- --uninstall

Stops and removes the service, parlons-pair and the fleet runtime directory. Keeps /var/lib/parlons-node (identity, wallet, chats) and the jars in /opt/maxima. To erase the node itself, after backing up the seed: rm -rf /var/lib/parlons-node.

16Security checklist

  • The jar's SHA-256 was checked against §17.3 before it was activated.
  • The service runs as the unprivileged maxima user with the hardened unit (§7).
  • /var/lib/parlons-node is mode 700; identity.txt, gateway-token.txt, pair-code.txt, panel-ticket.txt and keets-mailbox/keypair are mode 600, owner maxima.
  • The wallet phrase and identity.txt are backed up offline and appear in no log, ticket or chat.
  • Inbound: only the P2P port, the relay port (TCP, and UDP on a fleet box), UDP 49737 on a fleet box, and 80/443 for a TLS front.
  • From outside, 9003, 9004, 9005, 9585, 9587 and 9602 do not answer (§12, step 5).
  • Whenever parlons.dex.port is set, parlons.dex.public (or parlons.dex.bind=127.0.0.1) is set too.
  • parlons.gateway.bind is 127.0.0.1; the admin RPC is never proxied; MDS is never bound publicly.
  • -Xmx is set and MemoryMax is above it (fleet: a further 1 GB).
  • parlons.node.public points at a URL that really routes to this box.
  • No secrets on the command line: passphrases and mdspassword live in mode-600 files.
  • parlons.node.selftest.send is not set.
  • One host runs this identity and this data directory. The archive from §11 is never restored onto a second live box.
  • The provider firewall agrees with ufw/firewalld.
  • An admin pairing password is set; old invitations are used or discarded.
