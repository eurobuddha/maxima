Verified file delivery and exclusive payment currency — 2026-10-26

Behavior
An authenticated file-control message identifies the transfer and SHA-256 digest,
never the file key, filename or bytes. Completion is emitted after successful
verification, persisted and retried until acknowledged. A sender stops serving
after every intended recipient confirms, unless Keep sharing is enabled.
Share again reopens the same transfer. Local verified files remain available.
Cloud hosts wait for the receiving device to verify its copy; host download alone
is insufficient. Android owner confirmations persist and retry while the chat is
open and after reopening it. Browser confirmations retry while its sheet is open.
Transfer sheets display downloaded/verified, stopped, waiting or unavailable state.
This change does not add operating-system completion notifications.

Keets 1.2.12 isolates each private transfer in a separate Corestore. Closing it
stops historical-block replication without interrupting other files/photos.
The 128-transfer cache bound remains. Explicit removal of a stopped transfer frees
its cache and slot. Files originally published on the legacy shared drive cannot
be stopped independently; send them again with the updated node. Both ends need
receipt-capable clients for automatic completion. Old clients retain manual use.
File bytes remain P2P; controls use the existing encrypted chat transport.

Payment fix
The shared PaymentCurrency group assigns stable IDs before adding either radio
button, then selects Minima through RadioGroup. Both Android apps use it in their
chat and wallet send screens. The token ID is derived from that same selection.
No real payment was sent during validation.
